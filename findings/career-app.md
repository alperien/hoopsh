## CRITICAL server.ts:230 - /api/career/save is not gated on a running career sim; a mid-run save writes a torn mid-week state
Every other career mutation checks the loop: /api/career/new and /load 409 while a sim runs (server.ts:195, 213), /api/career/choice 409s (server.ts:306). The save route (server.ts:230-237) has no `state.careerSim.running` check, and the client never disables it either: the masthead save button and the `s` key call `api.careerSave()` with no `advancing` guard (app.js:416-428, 444 — only the two advance buttons are disabled, app.js:253-256). `advanceCareerWeek` mutates `career` across many await points (week.ts:238 `await sim(jobs)` after allocation is already debited; nbabridge.ts:501-511 between each of the seven `advanceDay`s; tick.ts:473 between fast days), so a save landing between awaits serializes a state no whole-week replay can reach: allocation paid but games unplayed, or 3 of 7 league days advanced with the clock not yet incremented. Loading that save and advancing re-runs `resolveWeek`/`resolveNbaWeek` for the same week: `resolveAllocation` charges the week's practice/slot costs and banks training a second time (week.ts:120-152), and the NBA path advances seven MORE league days, permanently drifting the career/league sync. `circuitWeekJobs` skipping played games (circuits.ts:722-723) prevents regrading but not the double allocation. This silently breaks the mode's flagship identity — "CareerState = f(seed, choiceLog)... the acceptance harness replays that equality as a gate" (CAREER_INTERNALS.md:8-11) — through a first-class UI control during the most common long operation ('sim ahead'). Mitigation that keeps it from firing every time: the end-of-run autosave (server.ts:318-319) overwrites the same default name, so the torn file survives when the user saves-and-quits mid-run or the run errors (the error path skips the autosave, server.ts:320). The acceptance replay gate cannot see this: it drives the package API directly, never the HTTP seam. The franchise twin (/api/save, server.ts:456-463, no `state.sim.running` check) has the same tear; noted here since it is one missing guard away in the same file.
Breaks: a save, and the determinism identity the save format claims (saves.ts:4-6 "deterministic to reproduce").

## HIGH docs/CAREER_INTERNALS.md:147 + nbabridge.ts:356/trust.ts:129 + plan.js:94 - the NBA-phase approach card is a one-shot; the documented UI resend does not exist; the standing card freezes at draft entry
Three surfaces disagree, and the player loses the mode's central lever for the whole second act. (1) The doc trap says "The approach card is consumed by the FIRST grade after it is set (nextApproach is for one game); the UI resends per game night" (CAREER_INTERNALS.md:147-148). No screen or shell code resends: the only `setApproach` sender in the UI is the plan screen's click handler (plan.js:94-109); the advance loop (app.js:312-336) posts nothing, and choices are 409'd while the loop runs anyway (server.ts:306), so a resend per game night is impossible during 'sim ahead'. (2) Pre-NBA this is fine because the felt-loop fix made the card sticky: resolveWeek captures it once, grades every game of the week against it, and folds it into `career.approach` at week end (week.ts:14-23, 232, 287-297). (3) The NBA bridge never got the fix: `advanceMyGameDay` reads `career.nextApproach ?? {...career.approach}` per game day (nbabridge.ts:356), `gradeMyGames` calls `updateAfterGame(career, record)` without the card (nbabridge.ts:410), which takes the legacy path that consumes `nextApproach` on the FIRST grade — including a DNP grade — and never folds it (trust.ts:129-130); no code in the NBA phase ever writes `career.approach` (the week.ts:290-296 fold runs only on the pre-NBA path). Net effect: post-entry, a dialed card applies to exactly one game; every other NBA game — the majority even for a user who re-dials weekly, since NBA weeks hold 2-4 games — simulates and grades on `career.approach` frozen at whatever the last pre-NBA week folded (a college/euro card, or neutral 50s). Sim and grade stay consistent game-by-game (no adherence whiplash), so nothing visibly errors; the agency loop just quietly stops working, which is precisely the felt defect the week.ts header documents fixing. The acceptance pilots mask nothing but test nothing here either: they resend only while a circuit is live (career-acceptance.ts:161-163), so no gate exercises the NBA card path. The plan screen's toast "the card is set for the next game" (plan.js:102) matches the legacy semantics and contradicts week.ts's sticky doctrine — pick one and make all four surfaces (doc trap, week.ts, nbabridge/trust legacy path, UI copy) say it.
Breaks: a documented guarantee (the sticky-card fix week.ts:14-23 vs the legacy NBA path), the doc trap's claimed compensating behavior, and the NBA-phase agency loop.

## MEDIUM server.ts:161 - foldSeason nulls the circuit before the server archives the fold week, losing every season's championship game
The session archive exists because "Folding a circuit nulls it; game records for past seasons live only in the app's session archive" (CAREER_INTERNALS.md:145-146). But the archiving loop reads `career.circuit?.results[gid]` (server.ts:162) AFTER `advanceCareerWeek` returns, and inside that call `foldSeason` already ran: the bracket final sets `complete` (circuits.ts:993-995, via applyCircuitResults), and foldSeason archives the summary and sets `career.circuit = null` (tick.ts:268-288) before the digest reaches the server. So the games of the completion week — the title game, every season — are never copied into `state.careerGameArchive` and never get their replayFile stamped. Consequence: the grade table (plan.js:138-147, slice(-15) always includes the final) and phone refs link to `#/career-game/<final>` which 404s ("no result for that game", server.ts:338) the moment the season folds, in the same session, for the climactic game the archive was built to keep. Fix shape: stamp/archive from `digest.gamesPlayed` against both `career.circuit?.results` and a pre-null capture (or have foldSeason hand the records to the digest).
Breaks: the documented session-archive mitigation for the fold trap; dead links on every season's biggest game.

## MEDIUM server.ts:178-183 - stop-on-window scans only the last 8 events; a window opening on a decorated year wrap can be buried and the sim never stops for it
`runCareerAdvance` decides the 'window' stop from `career.events.slice(-8)`. Contract-window events fire once per decision id with a stable id (nbabridge.ts:424-459, pushEventOnce), and after `resolveNbaWeek` returns, the same career week can append the fade event plus the year-wrap block — accrueSeason money events, harvestSeasonHonors' one-event-per-honor, a phase transition (tick.ts:479-490) — so a window opening on an award-heavy wrap week can sit more than 8 events from the tail when the check runs. The check for that week is the only one that will ever see it: next week the slice holds newer events, and `seenWindows` is only updated when the stop fires (server.ts:180). Consequence: 'sim ahead' sails past the window; unless the user happens to open the office (which scans two years of pages, office.js:33-45, 74-76), a player option resolves by the documented silence convention — "an unanswered player option rides as exercised at the rollover" (nbabridge.ts:62-63) — over the player's head, which is exactly the agency loss the stop exists to prevent. Scan the digest's own event ids (digest.events, which resolveNbaWeek fills with the week's whole append) instead of a fixed tail; the `windowOpened` double-`some` at server.ts:178-179 is also redundant.
Breaks: the stop-on-decision contract of the advance loop for the decision class with the harshest default.

## What is done well
- The read-model discipline is real: every /api/career/* payload is hand-trimmed (careerSummary, meView, circuitView, stockView), no route ships the league players map, `potential` never leaves the server on any path, prospects get ranges only, and `scoutSeed` is stripped from team views. The scouting-fog RPG hook survives the API surface.
- The totals-vs-per-game trap is handled correctly by every consumer found: historyCard divides by gp with a did-not-play guard (widgets.js:80-83), the acceptance ppg helper guards gp=0 (career-acceptance.ts:118-119), and all shooting percentages in both view layers guard zero attempts (career-views/summarizeCircuit, views.ts:63-65).
- plan.js's deviation readout is a faithful mirror of approach.ts `deviationFrom` (same five dials, same overflow×2, same 0-100 clamp), so the price the user sees while dragging is the price the sim grades — the right way to build a UI mirror.
- new.js mirrors the creation law exactly (budgets 60/110/160, base 38, cap 68 ⇒ alloc ≤30, height 68-90, the 190+(h−74.5)×7 ±45 frame line with 140/330 absolutes) and still treats the server as the validator, rendering its multi-error refusals inline.
- Choice handling is uniformly attempt-and-learn: every screen posts, renders `result.errors` inline, and never trusts client state over the server's no (office.js's settled-map "learned: the window is not open" is a nice pattern).
- The 409 discipline on time is properly two-way: franchise advance/action/save are blocked under a career, career choice/new/load are blocked under a running loop, and the career/franchise sim loops lock each other out (server.ts:315).
- The event-log paging math is exact (verified lossless and newest-first by enumeration), and money.js's reverse-accumulate-reverse running total is correct for a newest-first payload.
- saves.ts is small and honest: shape-discriminated listing that never dies on a bad file, and the abroad rebind is precisely scoped to the one object that is genuinely double-mapped.
