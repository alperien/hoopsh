## CRITICAL packages/app/src/career-acceptance.ts:200 - The flagship reacting-world gate is tautological: the observable it reads is cleared by the same function that would have to violate the invariant
The harness's live invariant check (`career.coach.roleClock.above >= t.reactGames || .below >= t.reactGames`, lines 199-202, gated at line 287) re-reads a counter that trust.ts unconditionally zeroes at the reactGames threshold inside the same call that increments it. In `updateAfterGame` the clock increments at trust.ts:181-190, and the ladder block at trust.ts:196-238 is exhaustive over "clock >= reactGames": promote (idx < top, resets at 198-200), demote (idx > 0, resets at 213-214), at-ceiling above (idx === top, resets at 229), at-floor below (idx === 0, resets at 235). At most one clock is nonzero at any time (each increment zeroes the other, 183/186; decay preserves min = 0), so the else-if chain always reaches the matching reset arm, and nothing between increment and ladder can throw. Therefore after every `advanceCareerWeek` return the clocks are strictly below reactGames — `invariantBreaches` is mathematically unreachable and the fleet gate CANNOT fail. What it cannot detect: (a) a regression that keeps the reset but drops the role move (delete trust.ts:198 and the gate stays green while hot players stay buried — the exact failure CAREER.md calls "the single most immersion-critical property"); (b) grading silently skipping played games (week.ts:243 `if (!record) continue`, nbabridge.ts:407 skip on missing result — the clock freezes below threshold and a hot player is ignored forever); (c) legal clock wipes mid-streak by roster events — every coach change zeroes roleClock (tick.ts:319 installNextCoach, nbabridge.ts:285 freshCoach on trade/coachChange/signing), which the dispatch's "does a roster event legally reset the clock" question answers YES; the gate cannot distinguish a legitimate new-bench reset from an evasive one. Secondary: the check samples once per week AFTER the whole week resolves (up to 7 NBA game days per advance), so even a genuinely stuck counter mid-week would only be seen if it survived to week's end. An independent gate would recompute streaks from `coach.grades` (production per game) and assert a `kind: 'role'` event within reactGames of any above-band run — the data exists and is not consulted.
Breaks: the career mode's flagship acceptance gate; a gate that cannot fail per the severity scale.

- The determinism comparison is byte-level over the FULL state JSON including the embedded league — the strongest equality available — and the state shapes are all JSON-faithful (no Maps/Sets); the divergence locator (lines 256-259) prints the first differing character with context, which turns a red gate into a debuggable artifact.
- runner.ts is a model worker pool: per-job seeds, contiguous slices, results re-sorted by submission index (runner.ts:79) so worker count provably cannot reorder folds; all-or-nothing failure policy with the job file kept for hand re-runs.
- The week/grading card-consistency fix (week.ts header, trust.ts:106-119) is exemplary repo practice: a measured felt-loop defect (adherence alternating 0/100), the fix, and the legacy path all documented where they live.
- The injury stream keyed per game rather than per week (week.ts:154-161) fixed a real halved-hazard defect and says so with the measurement.
- The script's energy-adaptive rest rule (lines 155-158) is thoughtfully justified: the band measures the design, not script stubbornness.
- Reason strings are built from actual drivers (stock.ts's reason ladder, trust.ts's itemized note terms), so where the lint does look, it is looking at meaningful text, not boilerplate.
- Draft night reads my selection off the real transaction wire (tick.ts:251-259) instead of trusting a return value, and undrafted is a first-class narrated outcome.
