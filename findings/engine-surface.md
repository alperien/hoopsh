## MEDIUM packages/engine/src/sim/params.ts:2931 - deepMerge accepts prototype-named keys; JSON `__proto__` override pollutes Object.prototype
The unknown-key guard uses `if (!(key in base))`, and `in` consults the prototype chain. Worse: a JSON-parsed override `{"__proto__": {"toString": 1}}` (JSON.parse creates `__proto__` as an own key) passes the `in` check, the group branch recurses with base = Object.prototype, `'toString' in Object.prototype` is true, typeof (function) !== 'number' skips the finite check, and the assignment lands on Object.prototype — verified: `Object.prototype.toString` became the number 1 process-wide. Overrides are "built dynamically at runtime" for sweep/solve/era packs per the same comment, and era packs are data files. Fix shape: `Object.prototype.hasOwnProperty.call(base, key)` (or reject `__proto__`/`constructor`/`prototype` outright).
Breaks: the fail-loud contract of the config boundary for a class of keys, and — under a corrupt/hostile era-pack file — the entire process, unattributably.
